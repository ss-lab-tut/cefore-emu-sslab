# Gemini CLI Context: CeforeEmu

This document provides essential context for interacting with the CeforeEmu codebase. CeforeEmu is a network emulator based on Mininet for testing Cefore (Content-Centric Networking framework) deployments.

## Project Overview

CeforeEmu creates virtual network topologies with virtual hosts running Cefore daemons (`cefnetd`, `csmgrd`) to simulate content distribution scenarios. It supports linear and mesh topologies, including disaster simulations (host failures and recoveries).

### Key Technologies
- **Python 3.12+**: Primary implementation language.
- **Mininet**: Network emulation framework.
- **Cefore**: Content-Centric Networking framework (must be installed on the host).
- **NetworkX**: Topology algorithms and visualization.
- **uv**: Python package and dependency management.
- **Matplotlib**: Topology diagram generation.

## Project Structure

- `src/topo/`: Core topology implementations (linear, mesh, disaster).
- `src/config/`: Configuration loaders (JSON/YAML) and auto-generation logic.
- `src/log/`: Log parsing and CSV summarization tools.
- `configs/`:
    - `templates/`: Base configuration files for Cefore nodes (h0/h1/h2).
    - `examples/`: Sample JSON/YAML configuration files.
- `tools/autotest/`: Automated batch experiment runner (`run.py`) and analyzer (`analyze.py`).
- `logs/`: Default directory for experiment logs.
- `out/`: Default directory for autotest results and summaries.

## Building and Running

### Prerequisites
- Ubuntu 22.04 (recommended).
- Cefore installed and configured.
- Mininet 2.3.0 installed.
- Root privileges (`sudo`) are required for all Mininet-related scripts.

### Installation
```bash
uv sync
```

### Running Experiments

**Simple 3-node linear topology:**
```bash
sudo python3 simple-three-nodes-two-switch.py
```

**Mesh topology with disaster simulation:**
```bash
sudo python3 mesh-disaster-topology.py --config configs/examples/auto_experiment.yaml
```

**Key CLI Options for `mesh-disaster-topology.py`:**
- `--config <path>`: Load settings from JSON/YAML.
- `--no-cli`: Run in non-interactive mode.
- `--duration <sec>`: Duration of the evaluation phase.
- `--results-json <path>`: Output detailed results of each `cefgetfile` operation.
- `--num <id>`: Experiment ID (enables organized log directory `logs/ex{num}_seed{seed}/`).

### Automated Testing (Batch Runs)
The project includes an autotest framework for running multiple iterations of an experiment to collect statistical data.

```bash
sudo python3 tools/autotest/run.py \
  --base-config configs/examples/autotest_hot.yaml \
  --runs 5 \
  --duration 120 \
  --out out
```

### Log Summarization
Aggregate logs from one or more experiment directories into CSV format.

```bash
python3 log-summarize.py logs/ex1_seed42/
```

## Development Conventions

- **Root Access**: Always assume scripts involving Mininet require `sudo`.
- **Dependency Management**: Use `uv` for adding or updating dependencies.
- **Configuration**: Prefer YAML/JSON for defining experiments.
- **Host Templates**: Host-specific Cefore configs are generated from `configs/templates/`. Modify these templates to change default node behavior.
- **Log Naming**: Follow established patterns (e.g., `cefgetfile_h{host}_idx{id}.log`) to ensure correct parsing by summarization tools.
- **Caching**: Router nodes (odd-numbered or explicitly selected) run `csmgrd`. Cache expiration is controlled by `CACHE_DEFAULT_RCT` in `csmgrd.conf`.

## Important Artifacts
- `meta.json`: A snapshot of the configuration used for a specific run, found in the log directory.
- `results.json`: Detailed per-operation results (success, duration, down hosts) used for analysis.
- `summary.csv` / `summary.md`: Aggregate metrics generated by the autotest analyzer.
